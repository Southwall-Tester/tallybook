# 小账本 · 微信账单采集试验

一个 Android 原型，用于验证：**微信已经加载的账单详情数据，能否整理成自己的本地账本**。

第一版提供原生安卓界面、独立演示账本、微信详情回传解析、去重与状态更新、CSV 导出，以及可选的 Xposed 采集模块。数据保存在本机；App 未申请联网权限。

## 当前边界

- 解析器依据公开开源代码里的微信**单笔详情**结构实现。列表分页、独立后台请求、每日自动拉取尚未实现。
- 普通未 Root 手机可安装 APK，体验演示账本、导入受支持的 JSON 样本和导出 CSV。**单纯安装本 APK 不会自动读取微信。**
- 微信实时采集需要能运行 Xposed 模块的环境，并将模块作用域限定为微信。此项目不会给手机 Root，也不会修改或重新打包微信。
- 开源 Hook 切入点不等于当前微信版本一定兼容。真机成功与否以“实际收到交易”判断，开启开关、编译成功或模拟器测试通过都不代表微信采集成功。
- JSON 导入是开发验证入口，不是微信官方 CSV/XLSX 文件导入器。

## 先体验

1. 构建产物位于 `artifacts/tallybook-0.1.0-debug.apk`，安装后打开“小账本 · 试验版”。
2. 真实账本初始为空。选择“体验演示账本”，查看完全虚构的几笔交易；演示数据不会混入真实账本。
3. 在演示账本测试交易详情和 CSV 导出。清空操作只作用于当前账本，执行前会确认。

## 在已有模块环境中验证微信采集

1. 安装同一 APK，在模块管理器中启用“小账本”，作用域只选 `com.tencent.mm`（微信）。按管理器要求重新启动微信。
2. 回到小账本，在采集页开启 30 分钟采集窗口。
3. 正常进入微信 → 我 → 服务 → 钱包 → 账单，打开一笔已完成交易的**详情**。
4. 返回小账本，看最近采集时间、真实账本及诊断状态。重复查看同一交易应更新原记录，不增加第二笔。
5. 若已收到模块信号但没有交易，可能是当前微信页面实现或字段与原型不同。未知结构会拒绝入账，不猜金额或日期。不要将完整回调、登录凭据或带签名的链接公开粘贴到问题反馈中。

此流程读取查看页面正常取得的数据，不触发官方账单导出，不自动输入支付密码，也不处理刷脸验证。没有模块环境时无需为了体验界面而更改手机。

## 账本处理规则

- 金额以整数“分”保存，保留明确的正负方向，不使用浮点数计算。
- 有交易单号时以其生成稳定 ID；金额相同的不同订单仍是不同记录。
- 无交易单号时生成内容指纹，并标记待核对：完全相同的两笔记录可能无法区分。
- 同一 ID 再次出现会更新状态。退款、未完成、失败、转账等情况先标记待核对，不计入确认收支。
- 日期缺失或多组交易时间相互冲突时拒绝自动入账；不会用采集时间伪装交易时间。
- 只存整理后的必要字段，不保存整个微信回调、认证参数或跳转链接。
- 本版还没有多微信账号管理、银行账单关联、跨平台消费去重及退款金额核销。不要把原型汇总作为完整财务结果。

## Windows 构建

本项目固定使用 JDK 21、Gradle 8.11.1、Android Gradle Plugin 8.9.2、Android SDK 35 / Build Tools 35.0.0。工具放在项目 `.tools` 内，脚本不会修改全局 PATH。

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\bootstrap.ps1
powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

`bootstrap.ps1` 会下载官方工具并校验其摘要；首次构建需要联网下载依赖。测试及真机验证范围见 [验证记录](docs/VALIDATION.md)。工具链与 APK 不纳入源码版本库。

## 源码入口

- `core/`：微信详情回传解析、严格字段校验、完全虚构的样例及单元测试。
- `app/.../hook/WechatHook.java`：被动监听微信 WebView 回传；不更改微信函数参数或返回值。
- `app/.../capture/CaptureProvider.java`：本机写入桥接，只接受本应用或微信 UID；不向外提供账本查询。
- `app/.../LedgerStore.java`：SQLite，真实数据和演示数据分开存储。
- `app/.../MainActivity.java`：账本、采集、设置界面。
