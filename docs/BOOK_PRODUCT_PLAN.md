# 以《小狗钱钱》两册为依据的产品设计

状态：完整产品设计与首批原型范围说明。研究日期：2026-10-03。设计时的既有基线为 Tallybook 0.3.1；具体交付能力见 [README](../README.md)，工程验证见 [VALIDATION](VALIDATION.md)。本文的完整页面、数据结构、流程和阶段是发展方案，不能作为全部完成说明。

2026-10-04 的 0.5.0 开发把主导航改为「今天、账本、梦想、成长、复盘」。在首版愿望、成功日记、72 小时行动、每日准则和周复盘之上，加入实际收入的钱罐分配、期初资金、用途调拨、已记支出核销、赚钱项目实收与成本、手动资产债务盘点、月度回顾、追加与通胀试算、分散风险场景、消费债务示例及梦想图片预览。微信直接查询开发停止，查询/Hook 保存于历史标签后从当前应用撤下。

本次落地仍有明确范围：钱罐由用户选择已确认收入后分配，不自动读取银行余额；资产债务是可编辑盘点，不是完整贷款还款计划；方法指南仍含通用练习入口，未实现投资下单、多人资金池、学习笔记全文系统、目标归档或所有方法的专用子系统。生活费预留、手记梦想进度和钱罐余额独立表达，不能叠加为现金。构建、设备与使用验证结论以验证记录为准；下文未标为本次实现的完整流程仍是发展方案。

## 1. 产品方向与阅读依据

面向大学生和其他成年人，继续使用 Java 与现有原生 Android 界面，做一个本地的日常财务与行动练习工具：用户知道钱准备做什么，能记录实际收支、尝试创造收入，并通过回顾真实经历逐渐建立信心、判断力和习惯。账本是这些选择的事实依据。

第一册把愿望、赚钱能力、分配、积累、学习与行动联系起来；第二册进一步要求同时照顾物质生活与人的内在成长。产品应让这些方法在生活中发生，不以阅读卡片数量、连续签到或资产规模证明用户已经成长。

## 2. 五个主页面

建议底部导航为「今天、账本、目标、成长、复盘」。设置、数据管理及导入方式放在页面右上角进入；保持记账入口随时可达。以下均为建议结构。

| 页面 | 用户要解决的问题 | 主要内容与操作 | 与现有页面的关系 |
| --- | --- | --- | --- |
| 今天 | 今天有哪些值得做的小事，钱是否够当前安排？ | 本期可用生活费及数据完整性提示；当前重点目标；一个到期行动；当天准则；快速记账、写成功事实、记录行动结果。可选择只使用记账。 | 延续首页预算卡和消费试算，新增行动入口；不把五套表单同时展开。 |
| 账本 | 钱实际从哪里来、到哪里去、准备怎么用？ | 已确认收支、待核对记录、账户与内部转账、用途分配、待收款和债务信息的分区入口；每项显示来源与状态。 | 复用交易列表、手动记录、来源提示、导出能力；账户、分配等后续分阶段增加。 |
| 目标 | 我为何想实现它，下一步是什么？ | 愿望及理由、最多三个当前重点、用户自选图片或文字、梦想用途罐、目标行动；收入尝试可关联目标。达成后归档并选择下一方向。 | 由单一存钱目标逐步扩展；原有金额、日期、进度计算可复用。 |
| 成长 | 我已做成什么、学会什么、准备练什么？ | 成功日记、知识笔记、七条准则卡、承诺与帮助记录、收入能力练习及离线学习内容。默认展示自己的最近记录，方法说明按需展开。 | 新增能力；不建立人格分、财富排名或朋友价值表。 |
| 复盘 | 实际情况与原先安排哪里一致，下一步怎样调整？ | 每周财务与行动回顾；每月目标、用途分配、收入项目及学习回顾；查看事实、写自己的解释、只选一个下一步，能返回修改计划。 | 复用最近七天收支及分类汇总；增加用户保存的解释和后续行动。 |

页面文字使用成人日常语言，如「本周想完成什么」「这笔钱准备做什么」「我做了什么」。不强制使用故事角色、收集白色石头、宠物升级或儿童闯关。方法来源可以保留书中名称，主操作仍用具体动词。

## 3. 日常使用闭环

### 3.1 首次使用：先保留自主选择

1. 选择真实账本或虚构演示；说明此处记录的资金依赖用户提供的信息，不代表已连接所有银行账户。
2. 填写当前生活费周期及必要开销；可以先直接记一笔，不强迫完成全部引导。
3. 开始愿望清单。原书第一册第 1、2 章的练习是写十个理由并选三个重点；产品允许分次保存，不能要求为了凑数编造愿望。
4. 给需要资金的重点目标设置金额、日期和用途；没有金额的能力或关系愿望仍可保存为行动方向，不能强行换算价格。
5. 选择一个能在 72 小时内完成的小动作，例如列出申请所需材料、做一次需求询问或收集目标图片。提醒时间由用户决定。

### 3.2 每日：看方向、做一件事、留下事实

第一册第 5 章约十分钟的练习，可作为默认建议；第二册第 9 章强调每天只集中研究一条准则。两者合并在一个「今天」入口，不叠加成多项强制任务。

| 时机 | 用户操作 | 保存的结果 |
| --- | --- | --- |
| 开始一天或用户选定时间 | 看重点目标和当天准则；选择或继续一个小行动 | 具体动作、完成条件、可选时间与关联目标。当天准则允许改期或暂停。 |
| 实际发生收支时 | 手动记账或核对导入；收入确认到账后再选择是否分配 | 真实交易；经用户确认的用途变化。工资预期、待收款和模拟收益不自动进入可用现金。 |
| 行动之后 | 记录做了什么、结果如何、有什么阻碍 | 行动事实及可选的交易、笔记关联；单纯打开页面或点按钮不视为行动证据。 |
| 一天结束或下次方便时 | 写成功日记和一条新的理解，回看当天准则与自己的经历 | 第一册第 3 章建议至少五件成功小事，界面提供五个起步位置并允许增加；少于五件也可保存或留草稿，不自动生成不存在的成绩。 |

72 小时来自第一册第 5 章的行动要求，适用于拆小后可完成的事；它不是书中规定的消费冷静期，也不意味着大目标必须三天完成。逾期后可缩小动作、重新安排或取消，记录原因即可。

### 3.3 每周与每月：事实驱动的调整

每周复盘是本产品为日常使用增加的节奏；第二册的七天循环提供主题安排依据，不能据此声称原书规定了完整的财务周报。

每周流程：核对本周收支与未确认项 → 看目标及行动事实 → 回答「哪个做法值得保留」「什么条件阻碍了我」→ 选择一个下周调整。七条准则只展示自己的解释、实践经历和待思考的问题，不生成七维品格雷达图。

每月流程：检查生活费周期、用途余额、目标与待收/债务安排 → 回顾收入尝试的时间、成本、实际收入与反馈 → 查看成功日记及知识应用 → 调整下月安排。第一册的投资俱乐部月聚会可以启发定期讨论；个人软件不因此组织真实集资或自动分享账本。

学习后的最小闭环为「一个概念 → 用自己的话解释 → 选择一个现实应用或虚构实验 → 写结果与新问题」。阅读完成标记只表示看过，不能显示为已经掌握。

## 4. 第二册完整映射

### 4.1 七条准则与对应星期

下列名称与星期顺序直接来自第二册第 9 章《好老师的秘密》（`index_split_042.html`）。第一、二条在该章展开，第三至第七条在第 10 章《7条准则》（`index_split_043.html`）展开，附录（`index_split_048.html`）集中列出。每条都要能写自己的解释、真实经历和下一次行动；星期是默认节奏，用户可调整。

| 原书星期 | 准则名称 | 书中核心意思的简短转述 | 成人化行动示例与复盘问题 |
| --- | --- | --- | --- |
| 星期一 | 友好亲和 | 谦逊有礼，尊重他人，克制伤害与争执 | 在一次项目沟通中先听完对方再回应；事后写发生了什么、是否有需要修复的表达。可选择离开持续争执。 |
| 星期二 | 勇于承担 | 自己选择回应，把注意力放在能做、知道和拥有的事上 | 目标受阻时写清事实、可控部分和最小下一步；承认客观约束，不把经济困难或受到不公归咎于人格。 |
| 星期三 | 善待他人 | 看见优点，减少背后嘲讽，必要的批评保持礼貌 | 写下一次具体欣赏及依据；需要反馈时准备事实和改进建议，记录对方实际回应，不臆测他人心理。 |
| 星期四 | 帮助给予 | 主动帮助和表达善意，给予本身可以带来快乐 | 自选时间、技能、物品或金钱提供帮助，确认对方需要；记录做了什么。不能把有偿工作与无偿给予混为一项。 |
| 星期五 | 感恩之心 | 注意平常但值得珍惜的事与人，困难中也保留感激的空间 | 写一件具体获得的帮助或共同经历；可写感谢信草稿，再由用户自己决定如何表达。允许悲伤与复杂感受。 |
| 星期六 | 勤学不辍 | 阅读、成功日记、知识笔记和向他人学习；着重自身进步 | 记录一个概念及来源，用自己的话解释，并选一次应用；后续回看是否奏效、还不懂什么。 |
| 星期日 | 值得信赖 | 通过日常习惯、自律、守时和守约建立信任 | 选一个现实承诺，明确对象、时间和完成条件；完成后写事实，无法完成时主动重约或取消。 |

### 4.2 卡片方法怎样真正发生

第 9 章的操作是每张卡片写一条准则、一天专注一张、七天后从第一张重新开始，并长期持续；卡片正面写自己的理解，背面写特殊经历。书中用七种颜色区分卡片。产品可保留颜色辅助，同时必须有文字标签，避免只靠颜色辨识。

建议卡片有五项：原书短转述与出处、对我的意义、今天的一件实际行动、经历记录、下一次想试的变化。第 10 章另有把榜样记在卡片背面的做法，可以选填自己欣赏的人和具体品质。卡片可随经验修订，历史经历按日期保留；没有「人格达标」「七天通关」或自动判定善良程度。

| --- | --- | --- |

| 第 3 章《放大镜》；036 | 将无偿助人与有偿服务区分；在不顺的一天仍找出具体成功；认错与修复 | 帮助记录支持非金钱贡献；成功日记允许记录求助、学习、道歉等事实。读心、预知危险和逃离禁闭属于故事，不生成现实能力或任务。 |

| 第 5 章《前往加利福尼亚》；038 | 关系修复后的反馈、帮助中的合作、承认他人贡献；保留成功事实 | 一次行动可记录向谁求助及获得的帮助。飞机、营救和服药等情节不作为勇气训练或生活指导。 |
| 第 6 章《寄宿学校》；039 | 互相学习，人的不同长处可以互补；多重归属、宽容与共同点 | 可写自己的长处、想学习的能力和可请教的人；不要求填写国籍、宗教等身份，更不按身份评价。书中信仰论述不作为普遍事实测验。 |
| 第 7 章《好老师》；040 | 守时是尊重他人时间；讲授后立即练习、得到具体反馈；承担可控行动 | 承诺记录与小练习支持反馈、再尝试；可以记录实际限制和求助。学校考勤处罚不照搬为扣分、封禁或强制劳动。 |
| 第 8 章《危险》；041 | 在困难中求助；自行处理超出能力的危险会增加风险；成功记录也包含支持关系 | 行动计划可写需要谁提供帮助、何时应停止或换方法。现实挑战选可控场景，不能把冒险营救当作助人的必要条件。 |
| 第 9 章《好老师的秘密》；042 | 每日一卡、七天循环、个人解释与亲历事件；互相讨论和共同准备；以自身进步代替比较 | 实现可编辑准则卡和按日实践。协作可先用本地笔记记录，不需要社交平台、排名或自动共享个人记录。 |
| 第 10 章《7条准则》；043 | 七准则的后五项；榜样思考；非金钱帮助；阅读与两种笔记；守约；真实内容和实际行动导向的表达 | 关联帮助、知识、承诺与行动。表达练习可记录真实例子、希望对方采取的行动，先面向熟悉的人练习。魔法治病、动物惩罚等剧情不转化为知识或功能。 |
| 第 11 章《演讲比赛》；044 | 持续演练；人的价值不取决于财富或成绩；目标实现后选择新的方向；奖金用途分配 | 保存练习反馈并归档已完成目标；50/40/10 是人物的具体选择，用户可改，不能规定必要生活费只占 10%。不会因低余额或目标失败降低人的评价。 |
| 第 12 章《事件》；045 | 具体求助、合作；重新理解误会，感谢并修复关系 | 记录求助内容、实际支持和沟通结果；不把人物贴为永久好人/坏人，也不导入危险行动路线。 |

## 6. 资金与成长数据的概念

本节是数据设计建议。继续使用整数分存金额，日期与金额在保存前校验；明确账本归属、记录来源和状态。真实数据、虚构演示以及学习模拟三种空间必须隔离。

| 概念 | 需要记录什么 | 必须守住的边界 |
| --- | --- | --- |
| 账本空间 | 真实或演示的稳定标识、所属记录 | 交易来源与账本空间是两个概念。手动和微信记录可以属于同一真实账本，不能因为名称不同重复计钱。 |
| 交易与账户 | 实际收支、来源、确认状态、时间、金额；后续手工声明的钱所在账户 | 待核对、待收及预期收入不计入确认可用金额；自己的账户互转不是收入。没有可靠余额时不伪装已完成银行对账。 |
| 生活费计划 | 周期、期初可用、必要开销、已支付情况、用途预留 | 明确何时消耗预留，避免交易和固定/储蓄预留重复扣款。实际资金不足时保留差额，不把需要压缩为虚假的零。 |
| 用途与分配记录 | 日常、具体梦想、长期积累等用户选的用途；从哪里分到哪里、金额及来源 | 用途回答钱准备做什么，账户回答钱在哪里。一次分配只发生一次，总金额守恒；调配用途不会产生交易收入。用途金额不是另一个银行余额。 |
| 愿望与目标 | 原因、优先级、文字/用户图片、可选金额/日期、关联用途、下一步、归档状态 | 支持非金钱愿望；最多三个当前重点是书中练习的产品入口，其余愿望可保留；不为全部愿望强设金钱目标。 |
| 行动与承诺 | 动作、完成条件、起止/到期时间、对象别名、关联目标/准则、结果 | 区分计划、进行、完成、重约、取消；完成来自用户记录的事实。逾期没有人格含义。 |
| 成功日记 | 时间、具体事件、自己做的事、能力或支持、可选关联 | 用户可修改、删除、补记；不自动编造经历，不根据金额自动写评价。 |
| 知识与准则卡 | 方法出处、短转述、自己的解释、经历、榜样及待解决问题 | 书中观点、用户观点和数学演示分开。关系备注不是通讯录或他人档案。 |
| 收入尝试 | 需求、服务、投入时间/成本、预计/实际收入、反馈、下一步 | 预计收入与到账分开；记净收入时仍能看收入和成本，避免掩盖投入；软件不替用户接单、收费或联系他人。 |
| 周/月复盘 | 当期事实摘要、用户解释、选择的下一步、当时统计口径 | 复盘是自己的记录；交易后续更正时能识别统计已变化。历史文字不被自动改写为新结论。 |
| 学习模拟 | 明示虚构本金、投入、周期、收益/通胀假设、数学结果 | 结果只存在模拟空间，不回写真实交易或目标余额，不生成现实买卖指令。 |

迁移现有单目标时，应保留原名称、金额、日期和用户填写的进度。旧版手填已存金额不能凭空变成真实入金或历史用途分配；进入新模型前让用户核对并以标明来源的期初状态接续。更改目标与分配规则不追溯改写真实交易。

未来接入交易关联后，删除交易时相关日记不应一起消失；解除关联并说明原记录已不存在。删除目标或用途时，已有真实资金和历史交易不能被静默删除，需先处理用途余额、关联与归档。首批原型中，原有「清空账本」只清除原账本和生活费/单目标计划，保留独立的钱钱练习；练习提供逐项删除。未来如果增加清空成长记录的动作，应单独说明范围并确认，不能清空另一账本空间。

### 6.1 本地与隐私

- 保持本机存储、无账户注册要求；不为成长功能增加云服务、广告画像、联系人或位置权限。
- 日记、困难、债务、帮助对象等可能比金额更私密；界面只要求必要字段，对象可用用户自己的别名，不读取通讯录或推断关系。
- 图片仅在用户主动选择时用于自己的目标；不读取相册全量，不提交书中插图或个人目标图片到 Git。
- 导出前让用户选择交易、目标、日记等范围；默认交易 CSV 不悄悄夹带成长记录。新增结构化备份时写清格式与包含内容，不承诺尚未实现的加密能力。
- 错误日志、测试夹具、截图与 Git 不含真实账单、日记正文、关系信息、认证数据或原书全文；测试继续用虚构数据。
- 提醒由用户选择开启、时间和内容；锁屏默认不展示敏感正文。暂停提醒仍可使用记账和回顾。
- 本书方案不恢复已删除的屏幕读取功能。微信来源的后续接入独立参见 [接口研究记录](WECHAT_API_RESEARCH.md)，不能作为本设计已经实现的自动同步能力。

## 7. 不能机械照搬的规则

| 书中表达或情境 | 产品决定 |
| --- | --- |
| 吉娅的 50% 长期积累、40% 梦想、10% 开销 | 标注为书中人物示例，允许用户编辑；先辨明实际可分配的资金与必要支出，不要求大学生把全部生活开销压到收入的 10%。 |
| 债务情况下半存半还、降低分期 | 完整映射须带回第一册的条件：半存半还针对生活费之外的余钱及消费贷情境；合同义务和实际协商结果不能被模板覆盖。软件不自动延迟还款或注销账户。 |
| 固定收益、长期安全、市场回升等断言 | 学习时注明原书背景；计算采用显式假设，同时覆盖下跌、亏损和资金提前使用的情境。不保证 12% 收益、保本或某期限必然财务自由。 |
| 72 小时与 72 法则 | 前者是把决定落实成可完成的小行动；后者是特定正数利率下的近似估算。两者界面、单位、适用条件分开。 |
| 成功日记五项、约十分钟、长期一卡练习 | 保留方法建议，允许草稿、少量保存、补记、暂停与调整；不为凑数自动生成记录，不发断签惩罚。 |
| 勇于承担、感恩和友好 | 引导用户选择可控行动，同时允许描述不公、拒绝不合理要求和寻求帮助；不把困难解释为人格不足，也不要求压抑情绪。 |
| 关系账户、帮助和赠与 | 用于关注长期关系与实际付出，不算人情盈亏，不强制金额/比例，不以回报为条件。 |
| 自律、榜样与优秀品格 | 记录具体行为与个人反思；没有人格评分、财富排行榜、对朋友的等级评定或权威替用户作决定。 |
| 魔法、危险事件及医疗奇迹 | 视为叙事表达，不提供对应现实功能、挑战任务、预知能力或医疗知识。 |

这些限制必须体现在数据计算、默认值、操作和文案中，不能只在设置页加一段说明后继续输出承诺。

原书数值也需独立核算。第一册第 17 章的 20000 到 14128 实际下降 29.36%，不能把书中的约 25% 写成测试预期。分散示例中只有一项下跌、其余不变，是必须显示的条件。复利试算按自己的明确公式与舍入规则实现，不把故事数字当作现实预测。

## 8. 现有代码的复用与缺口

以下按设计时实际代码核对，只说明工程基础，不证明新流程已完成。

| 现有部分 | 可以复用 | 还缺什么 |
| --- | --- | --- |
| `MainActivity` 的首页、账本、目标、设置 | 原生布局、预算编辑、快速记账、消费试算、七天回顾、详情与数据操作 | 五页导航与日常闭环；新增内容较多时逐步拆出页面，避免继续把所有逻辑集中在一个 Activity。 |
| `LedgerStore` 与 `Transaction` | 本机交易、真实/演示隔离、来源与确认状态、整数金额 | 资金所在账户、内部转账、用途分配及待收/项目概念；跨来源重复处理仍需单独设计，不能在日记层猜测解决。 |
| `BudgetPlan`、`BudgetEngine` | 周期、预留、截至当天的确认记录、日均参考、消费试算 | 预留和实际用途变动的一致性；完整数据之前不能宣称消费一定使目标延后某天。 |
| `SavingsGoal`、`PlanStore` | 目标金额、日期和手动进度、预算保存、按账本隔离 | 多愿望与重点、图片、目标行动、分配历史、成长数据与可核对迁移。 |
| JSON 导入、CSV 导出 | 已支持格式的单笔导入、交易导出和本机文件交互 | 用户全部成长数据的可选备份/恢复；新格式版本与完整性校验；尚无微信官方 CSV/XLSX 导入能力。 |
| 现有 JVM、Android 集成和模拟器流程 | 金额/日期逻辑、存储、页面和集成验证基础 | 每阶段新增规则、迁移、暂停/恢复、删除关联及真实/演示隔离的对应验证。 |

首要缺口是目标的意义与行动、成功日记、实践后的回顾，以及用途分配和实际资金之间的可核算关系。增加静态书摘不能补齐这些缺口。

## 9. 分阶段交付与验收

每阶段按独立功能或修复提交，不一次性发布所有设想。用户批准开发范围后，继续遵守仓库的构建、模拟器验证、版本递增、历史 APK 保留和正常推送流程。本文本身不启动应用代码变更。

| 阶段 | 交付范围 | 可检查的验收条件 |
| --- | --- | --- |
| A：方向与行动 | 五页最小导航；愿望/重点目标；成功日记；72 小时小动作；可编辑的每日入口 | 可创建、暂存、修改、删除、跨重启继续；不到十个愿望/五件成功也可保存；三个重点之外的愿望仍存在；逾期可调整；真实与演示数据隔离；旧预算、交易、目标迁移后数值不变。 |
| B：资金分配闭环 | 用途罐、收入到账后的分配、目标进度与生活费的明确关系；必要的账户/转账语义 | 未到账/待核对收入不能分配成可用现金；同一来源不能重复分配；内部转账不增收入；整数分守恒与舍入明确；修改/撤销/删除能处理余额及关联；既有预留不重复扣款；旧手填进度不虚构历史交易。 |
| C：第二册实践闭环 | 七张准则卡、每日一条、个人理解/经历/榜样；承诺、帮助、感恩、知识应用；周/月复盘 | 星期和名称准确；用户能安排行动并保存实际经历；七天循环后仍可修订；可暂停/补记；没有人格分或比较榜；帮助不必花钱；草稿不自动发给任何人；复盘可产生并回到一个新行动。 |
| D：能力与学习 | 收入项目、待收与成本、书中债务情境练习、虚构复利/通胀/分散模拟、方法索引 | 预计/实收分开，净额可追溯到收入及成本；债务方案保留合同条件；模拟明确假设与单位并覆盖边界；结果不进入真实余额；不自动推荐买卖或承诺收益；第一册完整方法表中每项都有去向或明确边界。 |

阶段 B 完成前，可以继续显示旧版手动进度，但必须明确「手动记录，未连接分配」；不能把一个改名后的进度条称为已实现梦想储蓄罐。阶段 C 完成前，静态准则介绍只标为可阅读内容。阶段 D 的现实金融规则若需要扩展，另行核查当前官方资料；原书不是现行产品和规则的替代来源。

共同工程验收：运行相关计算和存储检查、`scripts/build.ps1` 及 [开发说明](DEVELOPMENT.md) 要求的模拟器检查；核对空状态、大字体、输入错误、日期边界、重启、数据隔离和迁移。每项结论分别标注已实现、JVM/模拟器验证、CI 验证或真机验证；工程测试通过不等于已证明能提高储蓄率、收入、幸福感或品格。

后续真实使用评估重点是用户能否独立完成一次目标—行动—记录—复盘，能否解释钱所在的位置与用途、是否发生重复计算、能否从自己的记录找到下一步。使用时长、签到次数和资产增长不能单独充当产品有效性的证据。

## 10. 首批原型的技术边界

愿望图片使用 Android 系统文件选择器 `ACTION_OPEN_DOCUMENT` 的 `image/*` 类型，只保留用户选中文件的持久只读 URI；不请求相册或广泛存储权限，不解码原尺寸图片。用户可打开关联图片、更换或移除关联；取消选择保留当前草稿。文件若移动、删除或授权失效，需要重新选择。设计依据：[Android Storage Access Framework 官方说明](https://developer.android.com/training/data-storage/shared/documents-files)。

学习试算使用用户填写的本金、固定假设年变化率和年数，年末四舍五入到分；支持零和负变化率，负数可以产生亏损。72 法则只在正数年率下显示粗略翻倍近似，不默认 12%。本期没有追加投入、费税或通胀购买力计算，也没有真实证券交易；结果不写入真实资金、收入、目标或分配记录。
